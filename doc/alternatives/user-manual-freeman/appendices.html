Appendix A: Serialization Formats

Data has to travel somewhere — into the system, out of the system, across a network. These are the containers it travels in.

A.1 Import Formats

When you bring data into a repository, the system will accept it in any of these forms:

Format Name File Extension(s) Description
Turtle.ttlTerse RDF Triple Language — a compact, human-readable way to write RDF. If you are going to look at your data in a text editor, this is probably the format you want.
RDF/XML.rdf, .xmlThe original XML-based serialization, established by the W3C. Widely supported, though not the easiest to read.
N-Triples.ntOne statement per line, nothing fancy. Simple and reliable.
N-Quads.nqLike N-Triples, but with a fourth column for the named graph. When your data has graph context, this is the format that preserves it.
TriG.trigTurtle extended to handle named graphs. The best of both worlds if your data has structure and you value readability.
JSON-LD.jsonld, .jsonLinked data expressed as JSON. A good choice when the people or systems you are working with already speak JSON.
CSV.csvPlain comma-separated values, transformed into RDF on the way in. Useful when your source data comes from a spreadsheet.

A.2 Export Formats

When you take data out of a repository, these are the shapes it can leave in:

Format Name File Extension Description
Turtle.ttlCompact RDF — good for human reading and many downstream tools
N-Triples.ntOne triple per line — simple to process with standard text tools
N-Quads.nqOne quad per line — preserves named graph context
RDF/XML.rdfThe XML form — broadly compatible with older systems
JSON-LD.jsonldJSON with linked data semantics — good for web applications
TriG.trigTurtle with named graphs — the right choice when graph structure matters
CSV.csvA table you can open in a spreadsheet

A.3 Query Result Formats

When a SPARQL query runs, it produces results. Here are the forms those results can take:

Format Media Type Best For
JSONapplication/sparql-results+jsonThe default — good for scripts and applications that consume the results programmatically
XMLapplication/sparql-results+xmlThe W3C standard result format — compatible with XML processing pipelines
SVGimage/vnd.dydra.SPARQL-RESULTS+GRAPHVIZ+SVG+XMLA visual graph of your data — useful for seeing structure and relationships at a glance
HTMLtext/htmlA clean, readable table — good for human review
CSVtext/csvComma-separated — for importing results into a spreadsheet
TSVtext/tab-separated-valuesTab-separated — for text processing and scripting
Turtletext/turtleFor CONSTRUCT and DESCRIBE query results
N-Triplesapplication/n-triplesFor CONSTRUCT and DESCRIBE query results
RDF/XMLapplication/rdf+xmlFor CONSTRUCT and DESCRIBE query results
JSON-LDapplication/ld+jsonFor CONSTRUCT and DESCRIBE query results
SSEapplication/sparql-query+sseS-expression format for the query algebra — a format for those who want to see how the system thinks about the query

Appendix C: A Glossary of Terms

Every field has its language. Here is what the words in this manual mean, stated plainly:

Term What It Means
AccountYour identity in the system — the name by which others know you, and the container that holds everything you have created here
RepositoryA named, persistent home for RDF data — the place where your quads live
ViewA named, persistent SPARQL query stored alongside a repository — a question you decided was worth keeping
QuadA single RDF statement made of four parts: subject, predicate, object, and the named graph it belongs to
TripleLike a quad, but without an explicit named graph — just subject, predicate, and object
SPARQLThe standard language for querying RDF data — it stands for SPARQL Protocol and RDF Query Language, if you were wondering
CollaboratorSomeone you have granted access to one of your repositories
TokenAn authentication credential meant for programs — a long string that serves the same purpose as a password, but is easier to manage in code
PaneOne of the tabbed panels in the interface — each one displays a distinct piece of work: an account, a repository, an editor
ImportBringing data from outside into a repository
ExportTaking data from a repository and sending it out into the world
Namespace PrefixA short alias for a long URI — so that instead of writing http://www.w3.org/1999/02/22-rdf-syntax-ns#type every time, you can write rdf:type

Appendix D: Further Reading

If you want to go deeper into the standards and technologies that underlie this system, these are the places worth visiting:

  • RDF 1.1 Concepts: The W3C Recommendation that defines the data model — what a triple is, what a graph is, how it all fits together
  • SPARQL 1.1 Query Language: The W3C Recommendation for querying RDF — the complete specification of the language you have been writing
  • Turtle: The W3C Recommendation for the Terse RDF Triple Language — a formal description of the format you have probably been using to read and write data
  • JSON-LD: The W3C Recommendation for JSON-based Linked Data — the bridge between the JSON world and the RDF world
A last word: The standards are thorough. They were written by people who thought about these things very carefully for a very long time. When you need precision, they are worth consulting. When you just need to get something done, this manual should be enough.
