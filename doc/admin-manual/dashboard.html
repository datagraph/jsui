2.1 Overview

Following successful authentication, the application navigates to the administrative dashboard at route /admin/. The dashboard is a single page organized into six tabs, each presenting a distinct operational domain. All substantive administrative work is conducted from this page.

2.4 Tab Loading Behaviour

Tab content is loaded lazily. The following rules govern when network requests are issued:

  • The Accounts tab is loaded immediately when the dashboard is first rendered, regardless of which tab is initially active.
  • All other tabs issue their initial data fetch on the first click that activates them.
  • Subsequent clicks to an already-loaded tab do not re-fetch data. Use the Refresh button within each tab to reload.
  • Certain tabs invalidate their cached data when upstream selections change: the Repositories tab re-fetches when the account selection changes; the Query History tab re-fetches when the repository selection changes. See Sections 2.5 and 2.6.

2.5 Cross-Tab Dependencies

Three tabs participate in a filtering relationship. Data selected in one tab constrains the data displayed in another:

  1. Checkboxes in the Accounts tab determine which accounts' repositories are fetched in the Repositories tab.
  2. Checkboxes in the Repositories tab determine which repositories' query history is fetched in the Query History tab.

This dependency chain is unidirectional: selecting or deselecting an account will trigger an automatic refresh of the Repositories tab if that tab has already been loaded. Similarly, changes to repository selection trigger a refresh of the Query History tab if loaded.

Navigation note: To follow the dependency chain in the intended order, work left to right through the tabs: select accounts first, then proceed to Repositories, then to Query History.

2.6 The Location Bar

The location bar occupies the bottom of every page. It serves two purposes:

2.6.1 URL Display and Direct Navigation

The location bar displays the current route. Clicking on it transforms the display into an editable text field. Typing a path and pressing Enter navigates the application to that route, using the client-side router. This is equivalent to typing in the browser's address bar but confines navigation to routes within the admin application.

2.6.2 Status Messages

The application writes transient status messages to the location bar. Such messages replace the URL display for a configured duration (typically three to five seconds) before reverting to the current route path. Status messages are issued by the following events:

  • Login initiation ("Authenticating...")
  • Successful authentication ("Authenticated as {name} ({level})")
  • Authentication errors
  • Operation confirmations and error reports from individual tab panels

2.7 Header Navigation

The header contains the following navigation elements when a session is active:

ElementDestination / Action
Logo / application titleNavigates to /admin/ (the dashboard root)
User linkNavigates to the user application at /ui/user
Log out buttonClears the session and navigates to /admin/login
Switching to the user application: The User link opens the standard user-facing interface. The admin session is independent; navigating to the user app does not terminate the admin session. Use the browser's back button to return.

2.8 Dialog Windows

Several operations within the dashboard open modal dialog windows. All dialogs share the following interaction model:

  • The dialog is overlaid on a semi-transparent background that obscures the page behind it.
  • Clicking the background (outside the dialog boundary) closes the dialog without taking any action.
  • A close or cancel button within the dialog likewise closes it without action.
  • Pressing Enter in a text input submits the associated form.
  • Pressing Escape closes the dialog.
