Appendix A: Route Reference

All routes within the administrative console are prefixed with /admin. The following table enumerates every route and its corresponding function.

RoutePageAccessDescription
/admin/loginLoginPublicAuthentication form. Unauthenticated requests to any protected route are redirected here.
/admin/DashboardAuth requiredThe main tabbed dashboard. Loads with the Accounts tab active.
/admin/manage/accountsDashboardAuth requiredAlias for /admin/ with the Accounts tab pre-selected.
/admin/manage/accounts/:account_nameDashboardAuth requiredOpens the account details dialog for the named account.
/admin/manage/repositoriesDashboardAuth requiredAlias with the Repositories tab pre-selected.
/admin/invitationsDashboardAuth requiredAlias with the Invitations tab pre-selected.
/admin/inviteDashboardAuth required (Admin)Opens the New Invitation dialog.
/admin/history/queriesDashboardAuth requiredAlias with the Query History tab pre-selected.
/admin/history/transactionsDashboardAuth requiredAlias with the Transaction History tab pre-selected.
/admin/logout—Auth requiredClears the session and redirects to /admin/login.

Appendix B: API Endpoints

The following table enumerates all API endpoints exercised by the administrative console, with their HTTP methods and purposes.

B.1 Account Endpoints

MethodEndpointPurposeAdmin Only
GET/system/accountsEnumerate all system accountsNo
GET/system/accounts/{account}/configurationRetrieve account configuration propertiesNo
POST/system/accountsCreate a new accountYes
DELETE/system/accounts/{account}Delete an account and all its repositoriesYes

B.2 Repository Endpoints

MethodEndpointPurposeAdmin Only
GET/system/accounts/{account}/repositoriesEnumerate repositories for an accountNo
POST/system/accounts/{account}/repositoriesCreate a repository under an accountYes
DELETE/system/accounts/{account}/repositories/{repo}Delete a repositoryYes

B.3 Invitation Endpoints

MethodEndpointPurposeAdmin Only
POST/invitationsIssue or resend an invitation to an email addressYes
DELETE/invitations/{email}Delete an invitation recordYes

B.4 Service History Endpoints

MethodEndpointPurpose
GET/system/accounts/{account}/repositories/{repo}/service_historyQuery execution history for a specific repository
GET/system/service_history/queries/{account}/{signature}Full SPARQL text for a query identified by signature
GET/system/service_history/transactionsSystem-wide transaction history
GET/system/service_history/imports?offset={o}&limit={l}System-wide import history, paginated

B.5 User Configuration Endpoint

MethodEndpointPurpose
GET/system/users/{accountName}/configurationRetrieve user configuration; used during login to determine administrator status

B.6 Request Headers

HeaderValueContext
AuthorizationBearer {token}All authenticated requests

Appendix D: Terminology

TermDefinition
AccountA principal entity capable of authentication; the identity under which repositories and views are organized.
AdministratorAn account whose administrator_of configuration property includes http://dydra.com. Administrators have write access to all console operations.
OperatorAn authenticated account that does not hold administrator designation. Operators have read-only access.
RepositoryA named, persistent container for RDF quads, owned by an account.
InvitationA record pairing an email address with a unique invite code, authorizing account creation by the recipient.
Invite CodeThe opaque string embedded in an invitation URL. Validated by the system when a new user completes registration.
Service HistoryThe system's persistent log of query executions, data transactions, and data imports.
Query SignatureA content-based hash identifying a unique SPARQL query text. Queries with identical text share a signature regardless of when or by whom they were executed.
TransactionA discrete data operation that inserted or removed quads from a repository, recorded with a UUID timestamp.
ImportAn operation that ingested an external data source into a repository, recorded with a UUID, source URI, and quad count.
Location BarThe editable URL field at the bottom of every page. Displays the current route; accepts typed paths for direct navigation; also serves as a transient status message display.
Pane / TabOne of the six named panels within the admin dashboard. Only one is visible at a time; switching is controlled by the tab bar.
Lazy LoadingThe pattern by which tab content is fetched from the server only on first activation, not at page load. Reduces unnecessary network traffic.
