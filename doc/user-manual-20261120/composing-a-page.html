Compose a Page

Overview

Compose is not a longer Ask. It takes a different shape of consent, for a practical reason: a page is a set of queries you authorise together, and no useful moment arrives at which to confirm the eighth of twelve. So you grant the authority once, up front, against a stated budget, and watch a meter spend it.

Press Compose in either exploration pane. It opens its own pane beside the one you were in, seeded with whatever you had typed — the prompt is usually most of the way there already.

The Four Stages

Gate 0 — the grant

Before the interface sends anything, you set — and see — what the run may do: which repositories it may read, how many calls, how many rows, how many bytes, and whether it may write. The meter beside the grant counts the spending as it happens, and you may revoke the grant while the run goes.

Phase 1 — the exchange

The model explores, through the same MCP endpoints an Ask uses, and proposes a page. The transcript shows every exchange — what went out, what came back, each call's arguments and payload. The run log beside it keeps the terse record you read the grant, the meter and the budget verdict against.

A turn in flight counts its own seconds and says what it waits on. The turn that writes the whole page is one request with no events inside it, so this is the stretch in which another surface would look as though it had stopped.

Gate 1 — the proposal

You review the whole page as one unit: every panel's query, every transform's source, every passage the model wrote. The gate lists the errors and the warnings. If you asked for a chart and the page draws none, it says so here — as a notice, never a refusal, since some results genuinely cannot carry a chart.

Phase 2 — the interface's own runs

You approve, and the interface runs the panels under your credentials. The page binds to what came back. It never shows you rows the model reported.

Gate 2 — the disposition

Keep it, save it, refresh it, or discard it.

What a Page Holds

Every region declares which of three kinds it is, and the page says so where you can see it:

  • bound — the interface ran that panel's query and filled the slot. Live: it refreshes.
  • derived — a value the model computed, written as a function the page can re-run. Still live, because the function runs again when the data does.
  • asserted — prose, judgement, a chart the model drew by hand. Nothing re-derives it, and the page marks it as the model's own work.

Where a Provenance Mark Comes From

Each region carries a mark, and the interface writes it, not the model. The interface keeps its own ledger of everything it put in front of the model — the prompt, the documentation it read, and every result with its repository, its query, its shape and its digest — and adds to that ledger through the compose and every revision after it. A region the model wrote takes its attribution from that ledger: written by the model from alice/sales, alice/costs, listing the sources in the order the run read them. Hover the mark to see them.

The mark keeps three statements apart, because they mean different things: the run read data; the run read nothing from any store; and no record exists for this page. A page carries its ledger into a downloaded copy and into its record, so a page you reopen from the archive carries the same evidence a fresh one does.

Beside that, the page carries the EU AI Act Article 50 line: which model produced it, when, and which repositories it read.

Revise a Page

The Revise box under the page is the location bar's instruction channel, with its target already set to the page it sits in — the same mechanism, so the same reply. Type what you want changed. Back comes a patch, not a new page: your scroll position, the tab you had open and your selection all survive, and the page numbers the revision and keeps it.

A change that needs new authority opens a gate. A presentational one does not.

A Page Stays Live

  • Refresh re-runs the panels under your credentials.
  • A control on the page may change a parameter — what a query asks for — and the page re-runs only the panels that depend on it, charging them against its own interaction budget. A page never rewrites its own query.
  • Where results have moved under a passage, the page marks it stale in place rather than quietly running it again.

Find a Page Again

A page you keep goes into your account's mcp repository with its panels, its transforms, its passages, the digests each was made from, and the ledger of what the interface showed the model. Reopen it and the interface runs the queries again rather than replay a snapshot, so a page reopened after the data moved marks its own prose on the way up. Open an earlier revision and it forks: it takes a new identity starting at revision 1, because carrying on from revision 2 of a page that reached revision 4 is a different page from there on.

What a Page Cannot Do

The page runs in a sandbox with no origin and no network. It fetches nothing, reaches no credential of yours, reads no storage, and speaks to the rest of the interface only through the one channel the interface opens for it. That is what makes it safe to run a page a model wrote.
