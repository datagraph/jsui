Ask a Model About Your Data

Overview

Dydra Studio can put a language model in front of your repositories. The model never reaches the store directly and never runs anything: it reads through the repository's MCP endpoint, it proposes, and the interface runs what you approve, under your own credentials. Everything on this page follows from that one rule.

The three controls, and what each one does

Under the prompt box sit three buttons. They are not three sizes of the same thing: they differ in what comes back, and in what you authorise to produce it.

ControlWhat it doesWhat you get backWhat it takes
Ask A question Prose, usually ending in a SPARQL query The read-only tool set, for one turn
Compose A page A live document: panels, charts, prose, provenance marks, revisions A grant with a budget, taken once before anything is sent
Past runs What already happened The record of past runs — nothing new Nothing: it asks no model and runs no query

In one line each:

  • Ask answers a question. The model explores the stores you chose and writes an answer. Any query it ends with has not run; running it, drawing a figure from it, or keeping it as a view are each your own separate act.
  • Compose builds a page. See Compose a Page.
  • Past runs shows what has already happened. It opens the record of past explorations, what the interface showed the model in each, and the endpoint's own journal of what it served.

Both panes print that same line under the buttons, so you need not remember it, and hovering any of the three gives you the longer sentence. Run is not one of these: in this interface it means one thing only, which is execute this SPARQL query.

Two further controls are modes rather than actions:

  • Figure changes what you ask the model for, not how anything is drawn. Tick it and the run tells the model that proposing a query is step 2 and drawing is step 3, and offers it query beside survey. The run reads the tick once, as it begins — tick it mid-run and nothing changes. Draw it… draws from any query in the transcript, ticked or not.
  • Stop raises a flag the run reads between rounds. A call already in flight comes back, and the record keeps it, because the store has already done the work. A stopped run says so, and hands you the prose it had.

Connect a Model

The connection is a setting of your account, not of a repository:

  1. Open your account page and choose the Connection tab, beside Profile, Configuration and Collaborations.
  2. Choose the provider and the model, and enter the credential.

The page holds the credential in memory for its own life. It writes it to no repository and to no browser storage, exactly as it treats your Dydra token. Close the tab and it goes.

Every surface that asks a model anything — the exploration panes, the location bar, a compose pane, the figure gate — draws on that one connection. None asks you for the credential twice, and where you have set none they all refuse in the same words and name the one place to set it.

A repository's MCP endpoint, its token and the exploration it holds open are a different matter, and stay with the repository. A repository's exploration pane says which connection it draws on; it does not own it.

Two Panes: One Repository, or Several

  • A repository's exploration pane opens from the repository page. It explores that one repository.
  • The account's exploration pane opens from the tab marked with the triple in the account's left margin. It carries the model connection and a choice of stores.
  • Both ask with the same button, Ask. The chip beside it says what a press would reach — no store chosen, the store's name, or across 3 stores, whose tooltip names them. The count is beside the verb rather than inside it, so one operation reads as one operation wherever you meet it.

The permitted set — the repositories you may choose from — holds your own repositories and the ones you collaborate on. The session reads it as it begins, and refuses a repository outside it by name, before anything runs.

Two worked examples follow: Ask Across Several Repositories and The same analysis, with a real model.

Ask From the Location Bar

The location bar is the one thing always on the screen, and it takes a question about data as readily as an instruction about the interface. It works out which you meant without asking you, and without spending a turn to find out:

  • A path, or a line beginning goto, navigates.
  • A line naming a repository — compare classes in alice/sales and alice/costs — is a question about data, and the reply names the stores it would read.
  • Anything else is an instruction about the interface. See the Arrangement manual.

Nothing runs until you press the button in the reply. That button performs the same operation as the account pane's Ask.

What You Learn Before Anything Runs

The interface discloses a run before it starts, in the terms the authority itself holds rather than a summary of them. It tells you:

  • which repositories the turn may reach, each with the account it belongs to;
  • how many rounds of tool calls it may take, and how many calls in all;
  • that it is read-only for this run;
  • that large results are read as their shape first, with the whole document available on request;
  • where it will write the record, and that you may stop the run while it goes.

Where a store offers no tools, the interface names it, and says why it offered none, before you read an answer that quietly leaves it out.

Watch a Run, and Read the Exchange

While a run goes, the status line names the store it is asking, says what it is asking for, and says how far into its rounds it has come — and it counts the seconds of a request still in flight, so a long turn does not look like a stopped one.

Below it, the transcript shows every exchange whole rather than summarised: what the interface sent the model, what the model answered, the arguments of each call it made, and the payload that came back. The same transcript appears in both panes and in a compose pane.

What You Can Do With an Answer

  • Draw it… on a query in the transcript renders a figure. The interface runs the query — never the model.
  • Add as a view keeps the query in the repository's catalogue as an ordinary saved view.
  • Keep the report renders the answer as a standalone HTML page carrying its own styles, no script and nothing to fetch, with the provenance line, the stores it read and the links to its record. One control opens it in its own window; the other saves it under a dated file name. Both panes offer it.
  • Past runs finds it again later.

Where you chose several stores, each query belongs to the store that produced it. Where the interface cannot settle which — the prose names two stores, or none — Draw it… and Add as a view refuse, and say what would make them work, rather than run one repository's query against another.

What the Run Records

A run can write itself as RDF into your account's mcp repository: the prompt, the documents the model read, each turn of its prose, and the payload of every call. Where a run reached several stores it writes one record per store, so you can attribute a cross-repository answer store by store. If it cannot write the record it tells you, and keeps the answer.
